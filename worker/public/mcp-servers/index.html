Popular remote MCP servers: readiness and token cost

Live, unauthenticated scans of 75 well-known remote MCP servers on 20 November 2026 with the open-source scanner. Click a server for its public page and badge.

Key numbers

  • 23 popular remote MCP servers scanned unauthenticated on 20 November 2026: 8 answer tools/list without login, 15 require OAuth.
  • 14 of 15 OAuth-protected servers had no pre-login readiness notes (401, WWW-Authenticate, OAuth protected-resource discovery); spec notes: Atlassian (Uses the older 2025-03-26 discovery (AS metadata on the MCP host, no RFC 9728)).
  • Tool-list cost per agent turn ranges from ~80 tokens (Astro Docs) to ~4,967 tokens (Hugging Face) among the open servers.
  • 2 of 8 open servers declare no tool annotations (readOnlyHint / destructiveHint); 3 of 8 have at least one tool description that is too long.
  • 52 more remote servers scanned on 20 November 2026: 17 open, 35 require login. Heaviest open tool lists: Gmail ~11,282 tokens (23 tools), Google Docs ~10,011 tokens (2 tools), Google Slides ~8,957 tokens (4 tools).
  • The long tail is different: see the State of public MCP servers report (official registry scan, 13 Nov 2026), where the longest single tool description was 27,638 characters.

FAQ

Which popular MCP servers are ready for production?

On 20 November 2026, 67 of the 75 servers in this list scored 90 or more on the live surface checks. Big vendors mostly get the basics right, but heavy tool lists are common (Gmail, Google Docs and Google Slides each cost about 9,000 to 11,300 tokens per turn); the problems we see are in the long tail of the registry (see the State of MCP report). Scores are automated surface checks, not a security audit.

How many tokens does an MCP server add to every request?

Its tool list is sent to the model on every turn. Among the open servers here it ranged from about 80 to about 4,967 tokens. Install fewer, smaller servers, or slim long descriptions.

Why do OAuth servers show no token cost?

Without a login we can only see the pre-login surface: the 401, the WWW-Authenticate header and the OAuth protected-resource metadata. Pro (coming soon) scans behind a test token.

How do I get my server listed or re-scanned?

Scan it on https://mcp-readiness.omer20sh.workers.dev/ and it gets a public page at /s/<host>/<path>. Add the README badge and the free GitHub Action to keep it from drifting.

Automated surface checks of what any MCP client sees before login: initialize, tools/list, an unknown method, a foreign Origin, a CORS preflight and OAuth discovery. No tool is called. Not a security audit, not an endorsement, and not affiliated with any listed vendor. Token counts are estimates (about ±10%).
